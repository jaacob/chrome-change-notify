# Safari (macOS) version

The Chrome extension source at the repo root is the single source of truth. This
directory wraps it in the native Mac app Safari requires.

## Layout

- `sync-resources.sh` — copies the shared extension files into `ExtensionResources/`
  (gitignored), which the Xcode project references.
- `build.sh` — sync + ad-hoc-signed Release build into `safari/build/` + opens the app.
- `DOM Change Monitor/` — Xcode project generated by `safari-web-extension-converter`,
  with two customizations:
  - `SafariWebExtensionHandler.swift` — receives `{type:'notify'}` native messages from
    `background.js` (Safari has no `chrome.notifications`) and forwards them to the app
    via the `dom-change-monitor://notify?...` URL scheme.
  - `AppDelegate.swift` — the app runs as a background agent (`LSUIElement`), posts the
    macOS notification via `UNUserNotificationCenter`, and opens the monitored page in
    Safari when the notification is clicked. Clicks must be handled by the app, not the
    appex: macOS cannot launch an appex from a notification click.

## Rebuild after changing extension code

```sh
./safari/build.sh
```

Then in Safari: Develop → Web Extension Background Content → reload, or toggle the
extension off/on in Settings → Extensions.

## First-time setup

1. `./safari/build.sh` (builds and opens the app; click Allow on the notification
   permission prompt)
2. Safari → Settings → Advanced → "Show features for web developers"
3. Develop → **Allow Unsigned Extensions** (re-enable after every full Safari quit —
   ad-hoc signing; a paid Apple Developer account would remove this step)
4. Safari → Settings → Extensions → enable **DOM Change Monitor**, then grant
   "Always Allow on Every Website"
